# SlimeLounge 网络安全维护基线

## 核心原则

1. 浏览器、WebSocket、HTTP 请求中的数值都视为不可信输入；筹码、鱼获、游戏结算、权限、库存必须由服务端校验和落账。
2. 任何后台接口都必须同时满足身份认证、角色授权和输入校验；“来自 127.0.0.1”不能等价于“公网用户不可访问”，因为反向代理本身通常连接自 127.0.0.1。
3. 公网只暴露反向代理的 HTTPS/WSS 入口。Node 8090 不应直接开放到公网；云安全组/防火墙只允许本机反向代理访问该端口。
4. 密钥、Cookie、设备令牌不写入日志；公开健康接口只返回必要状态。

## 当前 v0.3.9 边界

- `/api/local-admin/*`、`/api/network/info`：必须为直接 localhost，出现任何转发头立即拒绝。
- `/api/room/action`：认证、用户级限流、JSON 结构校验、消息类型白名单、游戏 action 白名单。
- WebSocket：同源校验、8 秒认证首帧、16 KiB 单消息限制、10 秒 120 条消息限制、设备认证。
- JSON API：仅接受 `application/json`，请求体最多 64 KiB；限制嵌套深度、数组长度、对象字段数和字段长度，并拒绝 `__proto__` / `prototype` / `constructor`。
- 钓鱼：服务端生成鱼、令牌和最终评分；要求有效游玩时长和操作心跳，并限制短时间结算数量。客户端 score 不参与结算。
- 交易、商城、牌局：最终钱包与库存均以服务端数据为准。

## 部署检查

- 生产环境设置 `SLIMELOUNGE_PUBLIC_ORIGIN=https://你的正式域名`。
- HTTPS 环境启用安全 Cookie（`SLIMELOUNGE_COOKIE_SECURE=1`，如部署脚本已自动设置则保持）。
- `SLIMELOUNGE_TRUST_PROXY=1` 时，只信任实际反向代理源；非本机代理必须明确配置 `SLIMELOUNGE_TRUSTED_PROXY_IPS`。
- 云防火墙/安全组禁止公网访问 Node 监听端口，只开放 80/443（如 80 仅用于跳转 HTTPS）。
- 定期升级 Node.js 与依赖并执行 `npm audit`；上线前执行 `npm run check`。
- `data.json` 与备份目录权限只授予运行服务的系统用户，不由静态站点暴露。

## 持续监控

重点观察 401/403/409/429/5xx、WS 认证失败、异常高频 room action、钓鱼短时结算上限触发和设备身份异常。400/401/403 本身不是“服务器慢”，应结合响应耗时和来源频率判断是否为攻击扫描。

发生疑似入侵时：先保留日志和备份，撤销可疑设备令牌/会话，轮换服务端密钥，再分析请求路径和数据差异；不要只封单个前端按钮，因为攻击者可以直接调用 API。
